# چالش: طراحی سرویس ویراستاری حقوقی با استفاده از مدل‌های زبانی بزرگ (LLM)

## مقدمه

در این چالش، هدف طراحی یک سرویس ویراستاری حقوقی است که بتواند با استفاده از یک مدل زبانی بزرگ (LLM)، کیفیت نگارش متون حقوقی را ارزیابی کرده و اشکالات املایی و نگارشی آن‌ها را شناسایی کند.

ورودی سرویس، متن کامل یک رأی یا تصمیم قضایی است و خروجی آن باید شامل نمره کیفیت نگارش، توضیح کلی، فهرست اشکالات شناسایی‌شده و خلاصه‌ای از تعداد و نوع اشکالات باشد.

تمرکز این چالش **تشخیص و گزارش خطاها** است و نه بازنویسی، اصلاح یا خلاصه‌سازی متن.

---

## ساختار پروژه

فایل‌های مربوط به پیاده‌سازی در پوشه `candidate_package/` قرار دارند.

برای شروع توسعه، وارد این پوشه شوید:

```bash
cd candidate_package
```

کد اصلی مورد ارزیابی در مسیر زیر قرار دارد:

```text
candidate_package/
└── starter_code/
    └── ClarityWritingEvaluator.py
```

فایل `ClarityWritingEvaluator.py` را تکمیل کنید. سایر فایل‌های موجود در `candidate_package` مانند `requirements.txt` و `.env.example` برای راه‌اندازی محیط و اجرای پروژه استفاده می‌شوند.

پوشه `public_tests/` شامل تست‌های عمومی است و فقط برای بررسی صحت پیاده‌سازی استفاده می‌شود. این پوشه بخشی از کد ارسالی شما نیست.

# هدف

کلاس زیر را تکمیل کنید (تعریف کامل این کلاس‌ها در `starter_code/ClarityWritingEvaluator.py` نیز موجود است):

```python
from typing import Dict, List
from pydantic import BaseModel, Field


class WritingIssue(BaseModel):
    incorrect_text: str
    correct_text: str
    issue_type: str
    explanation: str
    context: str


class WritingSummary(BaseModel):
    total_issues: int = 0
    by_type: Dict[str, int] = Field(default_factory=dict)


class ClarityWritingAnalysis(BaseModel):
    score: float = Field(ge=0, le=1)
    comments: str
    issues: List[WritingIssue] = Field(default_factory=list)
    summary: WritingSummary = Field(default_factory=WritingSummary)


class ClarityWritingEvaluator:

    def evaluate(self, decision_text: str) -> ClarityWritingAnalysis:
        ...
```

پیاده‌سازی شما می‌تواند از هر روش مناسبی برای تعامل با یک مدل زبانی بزرگ (LLM) استفاده کند.

# خروجی

تابع باید یک شیء از نوع

```python
ClarityWritingAnalysis
```

برگرداند.
این شیء باید شامل چهار فیلد ذکر شده در کلاس `ClarityWritingAnalysis` باشد (تعریف کامل کلاس‌ها در بخش «هدف» در بالا آمده است).

---

# توضیح فیلدهای خروجی

## score

عددی بین **0** و **1** که کیفیت نگارش متن را نشان می‌دهد.

نمونه:

| مقدار | تفسیر |
|-------|--------|
| 1.0 | متن بدون اشکال |
| 0.8 | چند اشکال جزئی |
| 0.5 | کیفیت متوسط |
| 0.2 | کیفیت ضعیف |

---

## comments

توضیح کوتاهی درباره کیفیت کلی متن.

نمونه:

```
متن از نظر نگارشی مناسب است، اما چند خطای املایی و نگارشی مشاهده می‌شود.
```

---

## issues

فهرست اشکالات شناسایی‌شده.

هر عضو این فهرست باید ساختار زیر را داشته باشد.

```json
{
    "incorrect_text": "...",
    "correct_text": "...",
    "issue_type": "...",
    "explanation": "...",
    "context": "..."
}
```

### incorrect_text

متن اشتباه.

---

### correct_text

شکل صحیح همان متن.

---

### issue_type

نوع خطا.

حداقل انواع زیر باید پشتیبانی شوند.

- املاء
- علائم_نگارشی

در صورت تمایل می‌توانید انواع دیگری نیز گزارش کنید.

---

### explanation

توضیح کوتاهی درباره علت خطا.

نمونه:

```
املای صحیح واژه «آیین» است.
```

---

### context

بخشی از متن که خطا در آن مشاهده شده است.

نمونه:

```
ماده ۲۶۵ قانون ایین دادرسی کیفری
```

---

## summary

خلاصه‌ای از خروجی.

ساختار آن باید به صورت زیر باشد.

```json
{
    "total_issues": 6,
    "by_type": {
        "املاء": 3,
        "علائم_نگارشی": 3
    }
}
```

که در آن:

- `total_issues` برابر تعداد کل خطاهای شناسایی شده است.
- `by_type` تعداد هر نوع خطا را نشان دهد.

# نمونه ورودی

نمونه‌ای از متن ورودی که به تابع `evaluate()` ارسال می‌شود.

```python
decision_text = """
پرونده کلاسه *تصمیم نهایی شماره *

شاکی:
اقای ج. پ. ف. فرزند ص.

مشتکی عنه:
اقای خ. م. س. فرزند ج. به نشانی *

اتهام:
ایراد صدمه بدنی غیر عمدی بر اثر تصادف رانندگی

بسمه تعالی

بتاریخ ۱۴۰۳/۰۷/۱۱ در وقت فوق العاده، جلسه رسیدگی شعبه * به تصدی امضا کننده ذیل تشکیل است، پرونده کلاسه * تحت نظر قرار دارد.

با توجه به تحقیقات صورت گرفته و بررسی اوراق پرونده، دادیاری ضمن اعلام ختم و کفایت تحقیقات با استعانت از خداوند متعال و با تکیه بر شرف و وجدان به شرح زیر مبادرت به صدور رای می‌نماید.

قرار جلب به دادرسی

در خصوص اتهام اقای خ. م. س. فرزند ج. به کد ملی *، فاقد سابقه کیفری موثر، آزاد با معرفی کفیل، دایر بر بی احتیاطی در امر رانندگی منجر به صدمه بدنی غیرعمدی موضوع شکایت اقای ج. پ. ف.، نظر به جامع اوراق و محتویات پرونده، تحقیقات صورت گرفته، گزارش مرجع انتظامی، شکایت شاکی، گواهی پزشکی قانونی، نظریه افسر کارشناس تصادف، اقاریر متهم در نزد این مرجع و سایر قرائن و امارات موجود در پرونده، اتهام انتسابی نامبرده را محرز تشخیص و مستندا به ماده ۲۶۵ قانون ایین دادرسی کیفری مصوب ۱۳۹۲ و مواد ۴۴۸، ۴۴۹، ۷۰۹، ۷۱۰، ۷۱۴ قانون مجازات اسلامی مصوب ۱۳۹۲ و همچنین ماده ۷۱۷ قانون مجازات اسلامی (تعزیرات) مصوب ۱۳۷۵ قرار جلب به دادرسی نامبرده صادر و اعلام می‌گردد.

قرار صادره قطعی و غیر قابل اعتراض می‌باشد.
"""
```

> **توجه:** نمونه فوق صرفاً برای آشنایی با قالب ورودی ارائه شده است. داده‌های مورد استفاده در ارزیابی نهایی متفاوت خواهند بود.

# نمونه استفاده

نمونه زیر نحوه استفاده از کلاس `ClarityWritingEvaluator` را نشان می‌دهد.

```python
from ClarityWritingEvaluator import ClarityWritingEvaluator

decision_text = """
پرونده کلاسه ...
"""

clarity = ClarityWritingEvaluator()

result = clarity.evaluate(decision_text)

print(result.model_dump())
```

# الزامات پیاده‌سازی

پیاده‌سازی شما باید شرایط زیر را رعایت کند.

## الزامات ساختاری

- خروجی تابع `evaluate()` باید از نوع `ClarityWritingAnalysis` باشد.
- تمامی فیلدهای تعریف‌شده در کلاس باید مقداردهی شوند.
- خروجی باید قابل تبدیل به JSON معتبر باشد.
- ساختار خروجی نباید تغییر کند.

---

## الزامات مربوط به امتیاز (score)

- مقدار `score` باید یک عدد اعشاری بین **0** و **1** باشد.
- هرچه کیفیت نگارش متن بهتر باشد، مقدار `score` باید بزرگ‌تر باشد.

---

## الزامات مربوط به issues

برای هر خطای شناسایی‌شده باید اطلاعات زیر ارائه شود:

- متن اشتباه
- متن صحیح
- نوع خطا
- توضیح خطا
- بخشی از متن که خطا در آن مشاهده شده است

---

## الزامات مربوط به summary

بخش `summary` باید با فهرست `issues` سازگار باشد.

به عبارت دیگر:

- `summary.total_issues` باید دقیقاً برابر تعداد اعضای `issues` باشد.
- تعداد هر نوع خطا در `summary.by_type` باید با تعداد همان نوع خطا در `issues` یکسان باشد.

---

## در صورت نبود خطا

اگر هیچ خطایی در متن شناسایی نشود، خروجی باید به صورت زیر باشد.

```json
{
    "issues": [],
    "summary": {
        "total_issues": 0,
        "by_type": {}
    }
}
```

# معیار ارزیابی

راهکار شما به صورت خودکار ارزیابی خواهد شد.

## ۱. ساختار خروجی

- خروجی از نوع `ClarityWritingAnalysis` باشد.

# اجرای تست‌های عمومی (Public Tests)

برای بررسی اولیه صحت پیاده‌سازی، مجموعه‌ای از تست‌های عمومی در پوشه `public_tests/` قرار داده شده است.

تست‌ها باید از مسیر ریشه چالش اجرا شوند:

```bash
python public_tests/run_all.py \
  --submission_dir candidate_package/starter_code \
  --output results.json
```

پارامترها:

- `--submission_dir`: مسیر پوشه‌ای که فایل پیاده‌سازی شما در آن قرار دارد.
    
- `--output`: مسیر فایل خروجی نتایج اجرای تست‌ها.
    

پس از اجرا، نتیجه تست‌ها در فایل `results.json` ذخیره خواهد شد.

توجه کنید که پوشه `public_tests/` فقط برای اجرای تست‌ها استفاده می‌شود و همراه با `candidate_package` در فایل ارسال نهایی نیاز نیست قرار گیرد.
