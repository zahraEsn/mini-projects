# عامل هوشمند تحلیل و مرور مقالات علمی

پیاده‌سازی چالش تحلیل و مقایسه مقالات علمی حوزه پزشکی/زیست‌شناسی: دریافت مجموعه‌ای از PDF و تولید یک گزارش تحلیلی جامع، تک‌فایل و کاملاً فارسی.

---

## نصب و اجرا

### ۱. نصب وابستگی‌ها

```bash
pip install -r requirements.txt
```

### ۲. تنظیم `.env`

```bash
cp .env.example .env
# سپس RHINO_CHAT_URL و RHINO_API_KEY واقعی را در .env قرار بده
```

### ۳. اجرا

```bash
python agent.py --input_folder ./input_pdfs --output ./sample_output/report.md
```

خروجی: یک فایل Markdown واحد (`report.md`) شامل خلاصه اجرایی، جدول استخراج اطلاعات، تحلیل روندها (به‌همراه نمودار)، شکاف‌های پژوهشی، نتیجه‌گیری و منابع.

---

## معماری راه‌حل

به‌جای یک تک‌فراخوانی بزرگ به مدل، pipeline به مراحل کوچک و مستقل شکسته شده تا هر مرحله روی داده‌ی تأییدشده‌ی مرحله قبل بنا شود، نه روی متن خام:

| # | مرحله | متد | نوع |
|---|-------|------|------|
| ۱ | تبدیل تمام فایل‌های PDF به Markdown | `convert_folder` (ابزار آماده) | بدون LLM |
| ۲ | استخراج ساخت‌یافته اطلاعات هر مقاله به قالب JSON (عنوان، سال، هدف، روش، داده‌ها، نتایج، محدودیت‌ها و ...) به‌صورت موازی همراه با Retry | `Agent._extract_all` / `Agent._extract_one` | LLM (موازی) |
| ۳ | تولید جدول مقایسه‌ای از اطلاعات استخراج‌شده | `Agent._build_table` | بدون LLM |
| ۴ | تولید نمودارهای متنی (Unicode Blocks) بر اساس داده‌های استخراج‌شده | `Agent._build_charts` | بدون LLM |
| ۵ | تحلیل روندها، الگوها و مقایسه مقالات | `Agent._analyze_trends` | LLM (موازی) |
| ۶ | استخراج و پیشنهاد شکاف‌های پژوهشی (Research Gaps) | `Agent._find_research_gaps` | LLM (موازی) |
| ۷ | تولید خلاصه اجرایی (Executive Summary) | `Agent._generate_summary` | LLM (موازی) |
| ۸ | تولید نتیجه‌گیری نهایی | `Agent._generate_conclusion` | LLM (موازی) |
| ۹ | اعتبارسنجی نهایی خروجی و تولید فایل `report.md` | `Agent.run` (مرحله نهایی) | بدون LLM |

مراحل مستقل از هم (روندها/شکاف‌ها، و خلاصه/نتیجه‌گیری) با `asyncio.gather` موازی اجرا می‌شوند تا زمان کل کاهش یابد.

### فایل‌های آماده (بدون تغییر استفاده شده‌اند)

- `pdf_to_markdown.py` → `convert_folder()` برای مرحله تبدیل PDF
- `rhino_provider.py` → `RhinoProvider` برای تمام فراخوانی‌های مدل

## تصمیم‌های طراحی کلیدی

### چرا نمودارها متنی (ASCII) هستند، نه تصویر؟

اولین نسخه نمودارها را با matplotlib رسم و به‌صورت PNG در قالب `data:image/...;base64,...` مستقیم داخل همان یک فایل Markdown embed می‌کرد. این روش دو مشکل ریشه‌ای داشت:

1. یک تصویر معمولی چند ده‌هزار کاراکتر متن لاتین (الفبای base64) به فایل اضافه می‌کند که نسبت زبان فارسی کل سند را به‌شدت و به‌ناحق پایین می‌آورد.
2. داده باینری base64 در معرض خرابی توسط هر پردازش متنی سراسری بعدی (مثل پاک‌سازی placeholder با regex) قرار دارد؛ چون حروف/ارقام base64 می‌توانند به‌طور تصادفی زیررشته‌هایی هم‌شکل با کلماتی مثل `xxx`/`tbd`/`todo` بسازند که با حذف‌شدن، طول و padding رشته را به‌هم می‌ریزند و تصویر را غیرقابل‌نمایش می‌کنند.

چون CHALLENGE.md صراحتاً «رسم متنی» را به‌عنوان روشی هم‌ارزِ matplotlib برای ساخت نمودار مجاز دانسته، نمودارها اکنون با کاراکترهای بلوک یونیکد (`█`) به‌صورت میله‌ای رسم می‌شوند (`_render_text_bar_chart`). این انتخاب هر دو مشکل را از ریشه حل می‌کند و همچنان الزام «یک فایل Markdown واحد» را کامل رعایت می‌کند، بدون هیچ وابستگی به matplotlib.

### مقاوم‌سازی در برابر خطای مدل

- **Retry با backoff:** هر تماس با مدل تا ۳ بار تلاش مجدد می‌شود (`MAX_RETRIES`, `RETRY_BACKOFF_SECONDS`).
- **Fallback فارسی معتبر:** اگر همه تلاش‌ها شکست بخورند، به‌جای crash یا متن خالی، یک fallback فارسی مشخص برای همان بخش برگردانده می‌شود.
- **اعتبارسنجی زبان (`_ensure_persian`):** اگر خروجی مدل به اندازه کافی فارسی نباشد، یک‌بار از طریق مدل بازنویسی می‌شود.
- **پاک‌سازی placeholder:** هرگونه اثر باقی‌مانده از الگوهای placeholder (`lorem ipsum`, `todo`, `xxx`, ...) از متن نهایی حذف می‌شود.
- **اسکلت اضطراری:** اگر کل pipeline (نه فقط یک فراخوانی) شکست بخورد، به‌جای عدم تولید هیچ فایلی، یک گزارش اسکلت با ساختار کامل و پیام خطای شفاف نوشته می‌شود.

### پایبندی به اطلاعات مقالات (ضد Hallucination)

- تمام پرامپت‌های استخراج و تحلیل صراحتاً دستور می‌دهند که فقط بر اساس متن ارائه‌شده پاسخ داده شود.
- هر فیلدی که در مقاله یافت نشود، دقیقاً با مقدار ثابت `"ذکر نشده است"` علامت‌گذاری می‌شود (نه حدس زدن).
- نمودارها مستقیماً از داده‌های ساخت‌یافته (خروجی JSON مرحله ۱) ساخته می‌شوند، نه از حدس مدل — تا با جدول بخش ۱ همیشه سازگار باشند.

## ساختار فایل تحویلی

```
submission/
├── agent.py                ← فایل اصلی (شامل کلاس Agent و CLI)
├── requirements.txt
├── README.md                ← همین فایل
└── sample_output/
    └── report.md            ← نمونه گزارش تولیدشده روی PDF های تست
```

## محدودیت‌های شناخته‌شده

- نمودارها صرفاً بر پایه فیلدهای ساخت‌یافته موجود (نوع مطالعه، سال انتشار) هستند؛ اگر این فیلدها در اکثر مقالات «ذکر نشده است» باشند، نمودار جایگزین (میزان کامل‌بودن داده) نمایش داده می‌شود.
- کیفیت محتوایی تحلیل (نه ساختار/حجم/زبان) به مدل Rhino وابسته است.
